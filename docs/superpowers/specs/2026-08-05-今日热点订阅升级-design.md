# 今日热点订阅升级设计文档

> **日期**：2026-08-05　**状态**：已确认方向（方案 B）　**关联**：[[30-项目/个人工作台]]
> 需求来源：用户反馈「今日热点没有经常更新」，希望接入更多外部焦点信息并支持按主题订阅筛选。

## 一、背景与目标

**现状问题**（已查证代码）：
1. 数据源仅 3 个（GitHub 热门新库 / Hacker News / V2EX），且前两个在 `api/hot.ts` 服务端、第三个仅前端直连
2. **缓存无过期时间**：`loadHot(false)` 只要读到 localStorage 缓存就直接返回 → 页面每次打开都显示旧数据，只有手动点「刷新」才重新抓取（F5 也不触发）
3. 无任何筛选/订阅能力

**目标**（用户已确认）：
- ✅ 自动更新：缓存 TTL 30 分钟 + 打开页面后台静默刷新 + 显示「更新于 HH:mm」
- ✅ 扩展信息源：内置源库 25+ 个（技术 / 学术 / 中文社区三类），用户勾选订阅
- ✅ 按主题订阅筛选：自定义主题关键词，顶部 tab 切换
- ❌ 不做：AI 摘要、Vercel Cron 预抓取、自定义 RSS 添加、进备份导出闭环

## 三、详细设计

### 3.1 源库（新建 `api/sources.ts`，仅服务端维护一份）

```ts
export type HotCategory = 'tech' | 'academic' | 'zh'
export interface HotSourceMeta { id: string; name: string; category: HotCategory; experimental?: boolean }
export interface HotSource extends HotSourceMeta { fetch: () => Promise<RawItem[]> }
export interface RawItem { title: string; url: string }
```

- 候选源清单（**实现时逐源验证可达性，稳定源 ≥15 个，不可达剔除或标 `experimental`**）：

| 分类 | 源 | 类型 | 稳定性 |
|------|----|------|--------|
| tech | GitHub 热门新库 | API（现有） | 稳定 |
| tech | Hacker News | API（现有） | 稳定 |
| tech | V2EX 热门 | API（现有） | 稳定 |
| tech | Lobsters | RSS lobste.rs/rss | 稳定 |
| tech | 36氪 | RSS 36kr.com/feed | 稳定 |
| tech | 少数派 | RSS sspai.com/feed | 稳定 |
| tech | 爱范儿 | RSS ifanr.com/feed | 稳定 |
| tech | Solidot | RSS solidot.org/index.rss | 稳定 |
| tech | cnBeta | RSS cnbeta.com/backend.php | 验证 |
| academic | arXiv cs.AI / cs.CL / cs.CV / cs.LG / cs.SE / math.IT | RSS export.arxiv.org/rss/... | 稳定 |
| academic | 机器之心 | RSS jiqizhixin.com/rss | 验证 |
| zh | 知乎热榜 | 非官方 API | experimental |
| zh | 豆瓣新片 | RSS douban.com/feed/review/movie | experimental |

- 抓取规则：`Promise.allSettled` 并发、每源 `AbortController` 8s 超时、每源最多 8 条、总量上限 60 条、单源失败静默跳过、整体失败由 `api/hot.ts` 兜底返回空 `{ items: [] }`
- RSS 解析：**手写轻量解析器**（零依赖）：`parseRssXml(xml: string): RawItem[]`——提取 `<item>` 块中的 `<title>` 与 `<link>`，处理 CDATA 与 HTML 实体；Atom 格式（`<entry><title>`）一并支持或标注不支持。纯函数，放 `api/rss-parse.ts` 便于测试

### 3.2 服务端 `api/hot.ts` 重构

```ts
// 响应形状（保持 items 顶层结构不变 → 首页 HotCard 零改动）
{ items: HotItem[]; sources: HotSourceMeta[]; fetchedAt: string }
// HotItem = { title, source, url, category }   ← category 为新增可选字段
```

- 订阅参数：`GET /api/hot?sources=a,b,c&topics=考研,LLM`（可选）。**服务端不强制过滤**——过滤在前端做（订阅配置已在前端掌握，避免请求参数复杂化）；`sources` 参数仅用于**服务端按订阅源抓取**（省流量、提速）。未传 = 全量源
- 保持 `Cache-Control: s-maxage=600`

### 3.3 前端 `lib/hot.ts` 重构

```ts
export interface HotItem { title: string; source: string; url: string; category?: HotCategory }
export interface HotResult { items: HotItem[]; fromCache: boolean; fetchedAt: string | null; stale: boolean; sources: HotSourceMeta[] }
```

- 缓存 key 升级：`wb:hot-cache` → **`wb:hot-cache-v2`**（旧缓存自动作废，避免格式冲突）
- 缓存值：`{ fetchedAt: string; items: HotItem[]; sources: HotSourceMeta[] }`
- `loadHot(refresh)` 行为：
  - `refresh=false`：读 v2 缓存 → 未过期 → 返回（`fromCache: true, stale: false`）；**过期 → 先返回旧缓存（`fromCache: true, stale: true`）**，页面据此静默触发后台刷新；无缓存 → 网络抓取（`fromCache: false, stale: false`）
  - `refresh=true`：强制网络 → 成功写缓存（`fetchedAt = now`）；失败 → 旧缓存降级（`fromCache: true`）
  - 网络链路：`/api/hot` 优先 → 失败 → 前端直连（保留现有 GitHub/HN/V2EX 三源直连逻辑作为最后一层降级，直连成功同样写缓存与 `fetchedAt = now`）
- 纯函数（可测试）：`isCacheFresh(cache, ttlMs)`、`filterByTopics(items, topics: string[])`（title/source/category 子串匹配，大小写不敏感，空 topics 不过滤）、`formatFetchedAt(iso)`
- **兼容保证**：`loadHot` 签名不变（`loadHot(refresh: boolean)`），首页 HotCard（`slice(0,4)`）**零改动**

### 3.4 订阅配置（数据层扩展）

```ts
// types.ts
export interface Subscriptions { sourceIds: string[]; topics: string[] }
// WorkbenchRepository 新增：
getSubscriptions(): Promise<Subscriptions>
saveSubscriptions(s: Subscriptions): Promise<void>
```

- **LocalRepository**：localStorage key `wb:subscriptions`，默认 `{ sourceIds: [], topics: [] }`
- **空 `sourceIds` 语义 = 订阅全部源**（UI「全选」时保存空数组；源库后续新增源自动包含）；部分勾选时保存选中 id 列表
- **SupabaseRepository**：新表 `wb_subscriptions`（见 3.5），RLS 本人读写
- **不进 BackupTables / exportAll / importAll**（保持 10 表备份闭环不变）
- 现有 repository 测试（local-repository.test.ts / supabase mock）同步扩展

### 3.5 数据库迁移（新建 `supabase/migrations/002_subscriptions.sql`）

```sql
create table if not exists public.wb_subscriptions (
  user_id uuid primary key default auth.uid(),
  source_ids text[] not null default '{}',
  topics text[] not null default '{}',
  updated_at timestamptz not null default now()
);
alter table public.wb_subscriptions enable row level security;
create policy p_select on public.wb_subscriptions for select using (user_id = auth.uid());
create policy p_insert on public.wb_subscriptions for insert with check (user_id = auth.uid());
create policy p_update on public.wb_subscriptions for update using (user_id = auth.uid());
create policy p_delete on public.wb_subscriptions for delete using (user_id = auth.uid());
```

- **绝对不改 001_init.sql**（用户已在 Supabase 执行过，改迁移文件会导致环境不一致）

### 3.6 UI（`hot.tsx` 重构 + 新建 `hot-settings-dialog.tsx`）

**热点页 `hot.tsx`**：
- 标题行：标题 + 「更新于 HH:mm」（fetchedAt 渲染，无数据不显示）+ 刷新按钮 + 「管理源」按钮
- 主题 tab 行：`全部` + 各主题关键词（chips 横向滚动，点击过滤）
- 列表项：序号 + 标题 + 来源标签 + 分类标签（tech→技术 / academic→学术 / zh→社区）
- 自动刷新：`useEffect → load(false)`，若 `res.stale` → 静默 `load(true)`（不显示 loading）
- 空态：无订阅源 → 提示「去管理源开启订阅」；全失败 → 现有 toast + 空态保留

**管理源对话框 `hot-settings-dialog.tsx`**（新建）：
- 源列表按分类分组，复选框勾选（全选/清空）
- 主题关键词：输入框 + Enter 添加 chip + 点击删除
- 保存 → `saveSubscriptions` → 关闭 → 触发重新加载
- 打开时 `getSubscriptions()` 回填

### 3.7 错误处理

| 场景 | 行为 |
|------|------|
| 全部源失败 | 显示旧缓存（`fromCache: true`）；无缓存 → 空态 + toast「热点源暂不可用」 |
| 单源失败 | 静默跳过该源 |
| `/api/hot` 不可达 | 前端直连降级（现有 3 源逻辑保留） |
| 订阅保存失败 | toast 报错，不关闭对话框 |
