# 资料库与文案对接 设计文档

> 日期：2026-08-05 · 状态：已确认（用户三节设计全部通过）· 范围：个人工作台 v1.1 + 视频文案提取器增强

## 一、背景与目标

**现状问题：**
1. 视频文案提取器（本地 Python + FunASR）转写出的文案**没有断句和标点**，"一坨"文本无法阅读、无法交给 AI 分析。已查证：SenseVoiceSmall 模型**原生输出带标点**（FunASR 官方明确不需要附加标点模型），故大概率是版本/后处理问题，需实测诊断。
2. 工作台「论文资料库」只有表面功能：仅 arXiv 搜索 → 收藏 → 状态三档（想读/在读/读完）。**没有**外部导入、文件夹分类、标签、摘要、全文内容。

**目标（用户原话提炼）：**
- 修好文案断句标点，让 AI 分析可用
- 整理好的文案（全文 + AI 总结）接入工作台作为资料
- 论文资料库升级为完整资料管理：外部导入、自定义文件夹分类、实用功能齐全
- **AI 处理留在本地电脑**（提取器侧 Ollama），工作台只做存储/展示/检索，不接云端 AI（避开 Vercel 美国区调 DeepSeek 被阻断的坑——Horizon 教训）
- 模块化、不冲突、可运行、延续莫兰迪淡雅设计

**已确认决策：**
- 文案资料与论文**合并一个「资料库」**（升级现有论文资料库）
- PDF 上传**默认关闭**（尊重用户对免费额度的顾虑）；后续经 Supabase Storage（1GB 免费池）可选开启，数据库 500MB 只存文本元数据
- 对接：v1 做**手动导入**（粘贴/上传文件），v1.1 可选做**一键推送**（提取器按钮 → Vercel API + token 鉴权）

## 二、范围

**做（v1.0.1）：**
- 提取器：标点修复（诊断 → 对症 → CT-Transformer 兜底）+ JSON 标准导出
- 工作台：wb_papers 表扩展 + wb_folders 新表 + 本地存储同构；「论文资料库」→「资料库」模块（文件夹树/列表/搜索/详情抽屉/三种新建入口）
- 对接：手动导入（粘贴文本 / 上传 .md/.json 解析填充）

**不做（YAGNI，明确砍掉）：**
- PDF 上传与在线预览（默认关；v1.1+ 再议）
- 一键推送（v1.1 增强，待 v1 稳定）
- BibTeX/引文导出、浏览器插件抓取、PDF 高亮标注、拖拽排序、首页新卡片
- 云端 AI 集成（决策：AI 全在本地）

## 四、数据模型

### 4.1 wb_papers 表扩展（不新建表 → 零数据迁移）

新增列（旧数据自动兼容，type 默认 'paper'）：

| 列 | 类型 | 说明 |
|----|------|------|
| `type` | text | `paper` / `note`，默认 `paper` |
| `folder_id` | text | 所属文件夹 id，可空 = 未分类 |
| `tags` | text[] | 标签数组 |
| `content` | text | 文案全文 / 笔记正文（可空） |
| `summary` | text | AI 总结，**存序列化 JSON 字符串**（`{"title","key_points","quotes","structure"}`），前端解析展示；可空 |
| `keywords` | text[] | 关键词（配合搜索，可空） |
| `file_url` | text | PDF Storage 路径（可空，v1 不启用） |
| `source` | text | 来源：arxiv / douyin / bilibili / manual / local… |

现有列保留：id / user_id / title / authors / arxiv_id / url / status / rating / note / created_at

### 4.2 wb_folders 新表

| 列 | 类型 | 说明 |
|----|------|------|
| `id` | text PK | genId() |
| `user_id` | uuid | auth.uid()，RLS 按用户隔离 |
| `name` | text | 文件夹名 |
| `parent_id` | text | 父文件夹 id，null = 根级（支持多级树） |
| `sort` | int | 同级排序 |

### 4.3 本地模式（IndexedDB）

local-repository 增加 `listFolders / createFolder / updateFolder / deleteFolder / moveFolder` 与文档对应扩展（移动文件夹 = 改 parent_id；移动资料 = 改 folder_id），与云端行为一致（复用 WorkbenchRepository 接口扩展）。

### 4.4 TypeScript 模型

```ts
export interface Folder { id: string; name: string; parentId: string | null; sort: number }
export interface Paper {  // 扩展
  type: 'paper' | 'note'
  folderId: string | null
  tags: string[]
  content: string | null
  summary: string | null
  keywords: string[]
  source: string | null
  // 现有字段保留
}
```

## 五、模块与页面

- `registry.ts`：`news` 模块下 id `papers` 子模块保留，名称「论文资料库」→「**资料库**」，路由 `/papers` 不变，icon 保持 Library
- 页面三段式：
  - **左栏**：文件夹树（根级 + 多级缩进；新建/重命名/删除/移动文件夹；"全部""未分类"固定入口；折叠）
  - **中栏**：资料列表（类型图标 📄/🎬、标题、作者/来源、状态徽标、文件夹归属；状态筛选 + 类型筛选；条目操作：移动至文件夹、编辑、删除）
  - **顶部**：搜索框（标题/作者/关键词/内容，防抖）
- **详情抽屉**（不跳页）：元数据编辑（标题/作者/链接/DOI/状态/评分/文件夹/标签）、全文与总结预览、删除
- **新建菜单**（`+` 按钮）：新建文件夹 / 添加论文（arXiv 搜索 or 手动录入 or DOI）/ 添加文案笔记（粘贴 or 上传文件）
- arXiv 搜索收进"添加论文"流程，主界面不再占位
- 首页不加新卡片

## 六、提取器改造

### 6.1 标点修复（诊断优先，三步）

1. **诊断**：`pip show funasr` 查版本；用一段真实音频跑 `Transcriber.transcribe`，检查模型**原始输出**（未过 clean）是否含标点
2. **对症**：
   - 原始有标点但后处理丢失 → 修 `postprocess/clean.py`（保留标点、正常断行）
   - 版本过旧导致输出无标点 → 升级 funasr 至新版（SenseVoice 原生标点）
   - 升级无解 → 挂 CT-Transformer 标点恢复兜底：`AutoModel(model="iic/punc_ct-transformer_zh-cn-common-vocab272727-pytorch")`（ct-punc-c 中文版，字符级，离线本地推理；注意词级 471067 版有句子分割/时间戳错位问题，**选字符级**）
3. **加固**：`test_clean.py` 加标点保留断言（清洗后句末标点/逗号不断链）；转写冒烟（真实短音频含标点输出）

### 6.2 JSON 标准导出（新增）

`output/markdown.py` 旁新增 `output/export.py`：`build_export_json(...)` 产出：

```json
{
  "version": 1,
  "type": "note",
  "title": "拟标题",
  "source_url": "…",
  "platform": "douyin",
  "summary": {"title": "…", "key_points": ["…"], "quotes": ["…"], "structure": ["…"]},
  "keywords": ["…"],
  "content": "带标点的全文…",
  "segments": [{"start": 0, "end": 3, "text": "…"}]
}
```

落盘与 Markdown 同目录（`<标题>.json`），Gradio 界面提供"复制 JSON"按钮（便于粘贴导入）。

## 七、对接通道

### v1：手动导入（主通道，必做）

- 「添加文案笔记」→ 两个入口：
  - **粘贴文本**：全文区 + 总结区 + 来源链接 + 标题（空标题自动取"未命名"）
  - **上传文件**：`.json`（标准导出格式，自动解析填充全部字段）/ `.md`（取 frontmatter 的 title/source/tags + 正文全文；解析失败明确报错，成功但缺字段留空可编辑）
- 本地与云模式均可用，零鉴权零配置

### v1.1：一键推送（增强，另行排期）

- 提取器 Gradio 设置页 +「推送到工作台」按钮（POST → Vercel `/api/import`）
- 鉴权：工作台「设置」页生成个人导入 token（存 Supabase 校验表，映射 user_id）；提取器配置 token + 工作台 URL
- Vercel 函数校验 token → 以 user_id 身份插入 wb_papers
- 仅云模式可用；v1 不做

## 九、边界与错误处理

| 场景 | 处理 |
|------|------|
| 删除文件夹 | 资料**移到"未分类"**，不级联删除（防误删；二次确认可手动清理） |
| 导入格式错误 | 明确报错提示（"无法解析该文件：xxx"），不静默丢弃 |
| 导入缺字段 | 留空可编辑，不阻断 |
| PDF 容量 | v1 无上传；后续开启时云端走 Storage 1GB 池并在界面显示余量 |
| 离线 | 本地模式天然离线；云模式依赖 PWA 缓存（现状不变） |
| 性能 | 列表懒加载、搜索防抖、TanStack Query 缓存（沿用现状模式） |
