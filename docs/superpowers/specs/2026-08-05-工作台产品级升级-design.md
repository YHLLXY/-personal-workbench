# 工作台产品级升级 设计文档

> 日期：2026-08-05 · 状态：设计中（A/B/C 三节用户确认中）· 范围：个人工作台 v1.2

## 一、背景与目标

用户希望工作台从"自娱自乐"上升到**产品级**：交互逻辑、功能强度、适用性都要达标。现状差距（审查结论）：

1. **账户界面空白**：设置页仅三行（外观/账号/数据模式）；移动端底部"我的"Tab 是空占位组件
2. **数据安全致命伤**：本地模式数据全在 localStorage——清浏览器缓存即全丢，无任何恢复手段；本地↔云端数据不互通
3. **交互强度不足**：首页 7 卡片各管各的，无"今日整体"聚合视图；无趋势统计；无使用引导

**目标（用户原话提炼）：** 不是改变原有功能，而是让功能**更好用、更实用、更贴合现状**；账户界面更丰富；达到产品级效果；与现有模块兼容；延续莫兰迪淡雅配色；**实用最关键**。

**已确认决策：**
- 升级档位：**A 个人中心 + B 数据安全 + C 总览聚合 全做**
- 不引入新图表库（趋势图纯 CSS/SVG 手绘）；不新增数据库表（零迁移）
- 提取器仓独立升级（标点修复 + JSON 导出）已完成交付，本 spec 只覆盖工作台

## 二、范围

**做（v1.2）：**
- A：个人中心页（资料卡/数据统计/数据管理/账号区/关于区）
- B：数据导出 / 导入恢复 / 存储占用显示（迁移 = 导出→导入闭环）
- C：今日概览条 + 本周趋势卡片 + 空状态统一

**不做（YAGNI）：**
- 命令面板扩展、首次使用引导（onboarding）、主题"跟随系统"三态、快捷键说明——列入 v1.3 候选，本版不做
- 多用户/协作、数据合并导入（只做覆盖式，简单可靠优先）
- 头像图片上传（首字母头像 + 6 色足够，零存储依赖）
- 任何现有模块逻辑改动

## 三、A 个人中心（设置页升级）

`/settings` 从极简页升级为完整个人中心（移动端"我的"Tab 同路由自动受益）。页面结构（max-w-2xl，莫兰迪卡片风）：

**1. 资料卡**
- 首字母头像：圆形背景 + 首字母（`user.email[0]` 大写），**6 色可选**（莫兰迪色板：雾灰蓝/鼠尾草绿/灰紫/暖沙/灰粉/浅棕）
- 昵称：可编辑；**存储走 Supabase Auth `user_metadata`（`auth.updateUser({ data: { nickname, avatarColor } })`）**——云模式随账号跨设备同步，零迁移零新表；本地模式存 localStorage（`wb:profile`）
  - ⚠️ **已查证的关键坑**：`updateUser` 后客户端缓存的 JWT 仍是旧 metadata，**必须紧跟 `auth.refreshSession()`** 才能读到新昵称/头像色（[Supabase 官方讨论确认](https://github.com/orgs/supabase/discussions/18877)）；保存成功后立刻 refreshSession 再更新本地 UI
- 邮箱展示 + 数据模式徽标（☁️ 云端同步 / 💾 本地存储）

**2. 数据统计卡组**（一行 2 个，共 6 项，实时聚合自现有 repository 数据）
- 待办完成率：`done / 总数`（百分比）
- 连续打卡：从 habitLogs 按日期回溯当前 streak 天数
- 专注总时长：focusSessions 分钟合计 → 小时（保留 1 位小数）
- 复盘次数：reviews 行数
- 笔记数：notes（未归档）行数
- 资料库：papers 行数

**3. 数据管理区**（B 节入口）
- 一键导出数据（JSON 下载）· 导入恢复（文件上传 + 覆盖确认）· 存储占用显示

**4. 账号区**（仅云模式显示）
- 修改密码：`auth.updateUser({ password })`，成功后提示重新登录；本地模式显示"本地模式无账号，数据仅存本机"
- 退出登录：`auth.signOut()` → 跳 /login

**5. 关于区**
- 版本号 `v1.2`、一句话简介、数据隐私说明（"数据仅你本人可见；导出文件请自行保管"）

## 四、B 数据安全（备份/恢复/迁移）

**核心设计：导出/导入闭环 = 备份 + 迁移一套机制**（本地导出文件可在云端模式导入，反之亦然，无需专门迁移代码）。

**1. 备份格式**（JSON，`src/lib/backup.ts`）

```json
{
  "app": "personal-workbench",
  "version": 1,
  "exportedAt": "2026-08-05T…",
  "mode": "local",
  "tables": {
    "tasks": [...], "habits": [...], "habitLogs": [...], "focusSessions": [...],
    "exams": [...], "notes": [...], "papers": [...], "folders": [...],
    "healthLogs": [...], "reviews": [...]
  }
}
```

- `app` 字段防误导入他应用文件；`version` 支持未来格式演进（导入时校验可解析）
- `mode` 记录来源（提示用，不阻断导入）

**2. 导出**
- `WorkbenchRepository` 接口新增 `exportAll(): Promise<BackupTables>`：
  - LocalRepository：读 localStorage 全部 `wb:` 前缀 key（补默认值后输出）
  - SupabaseRepository：并行拉取 10 张表（走当前会话，不弹登录）
- 下载：`Blob` + `URL.createObjectURL` + `<a download="workbench-backup-YYYYMMDD.json">`
- 文件内包含 exportedAt；不包含任何密钥/token

**3. 导入（覆盖式）**
- 接口新增 `importAll(tables: BackupTables): Promise<void>`：
  - LocalRepository：整体替换 localStorage（原子性：先全部写入，失败回滚旧快照）
  - SupabaseRepository：逐表全清后 `upsert` 写入（幂等）。**删除写法：** 利用 RLS 已限定 `user_id = auth.uid()`，用 `.delete().neq('id', '')` 即可安全清空本用户全部行（不需要也不应传 user_id 条件）；清理顺序"先子后父"（wb_folders 先于 wb_papers 无硬性要求——folder_id 无外键约束——但保持习惯）
- UI 流程：选文件 → 解析 → 校验（`app === 'personal-workbench'` + version 可解析 + tables 为对象）→ **警示确认："将覆盖当前全部数据，不可撤销"** → 执行 → 成功后全量 invalidate 查询缓存 + toast
- 校验失败：明确报错（"这不是工作台的备份文件"/"文件格式已损坏"），不静默

**4. 存储占用**
- 本地模式：`navigator.storage.estimate()` 显示已用/配额（KB/MB 格式化）；API 不可用时降级隐藏
- 云端模式：显示"数据在云端同步，无本地占用"

**5. 测试**
- `tests/backup.test.ts`：构造各表数据 → `buildBackup` → 序列化/反序列化 → `applyBackup` → 逐表比对一致；版本/app 校验失败用例
- `tests/local-repository.test.ts` 追加：exportAll/importAll 往返（含"导入后旧数据被替换"断言）
- `tests/supabase-repository.test.ts` 追加：exportAll 拉全表映射、importAll 清空+upsert 调用序列

## 五、C 总览聚合

**1. 今日概览条**（桌面首页顶部 + 移动端 OverviewHome 顶部，`overview-summary.tsx` 组件）
- 四格：今日待办 `完成 X / 共 Y` · 今日专注 `Z 分钟` · 今日打卡 `N / M 项` · 复盘 `✓ 已写` / `○ 待写`

- 卡片风格与现有一致（bg-card border rounded-2xl），点击跳转对应模块（待办→/tasks、专注→/pomodoro、打卡→/health、复盘→/review）

**2. 本周趋势卡**（`weekly-trend.tsx`，注册为首页卡片 span 5、desktopOrder 8）
- 近 7 天双系列：任务完成数（按 completedAt 本地日期）+ 专注分钟（按 startAt 本地日期）
- **纯 CSS 柱状图**（flex items-end，柱高 = 值/最大值百分比），双色（primary 任务、muted 专注），图例 + 日期标签（一/二…日）

**3. 空状态统一**
- 复用现有 `src/components/empty-state.tsx`，不新建

## 六、数据模型影响

- **零迁移零新表**：昵称/头像色走 Supabase Auth user_metadata（Auth 内置，随账号走）；本地模式存 localStorage
- `WorkbenchRepository` 接口新增 2 个方法（exportAll/importAll）——local/supabase 双实现
- 现有 10 张表结构与 RLS 均不动

## 七、错误处理与边界

| 场景 | 处理 |
|------|------|
| 导入非本应用备份 | 校验 app 字段失败 → 明确报错，不写入 |
| 导入损坏 JSON | try/catch → "文件格式已损坏"，不写入 |
| 导入中断（本地写一半失败） | LocalRepository 先快照旧数据，失败回滚 |
| 导入写入超 localStorage 上限 | `setItem` 抛 `QuotaExceededError`（Chrome 固定 10MB/origin）→ 捕获并提示"存储空间不足，建议清理由旧数据或改用云端模式"（[MDN：超限即抛异常、原数据不受损](https://developer.mozilla.org/en-US/docs/Web/API/Web_Storage_API)） |
| 云模式导入清表后写入失败 | upsert 逐表独立 try；失败表报错，其余已写入（提示用户重新导入） |
| storage.estimate 不可用 | 隐藏占用显示，不影响其他功能 |
| 统计卡数据为空 | 显示 0 或"—"，不崩 |
