# 启动动画「太阳」专项调研与改进方案

> 调研日期：2026-09-02
> 诉求：用户反馈进场动画里的卡通太阳「太扎眼，和现在的版本不吻合」。
> 本文只做调查与方案设计，**不含代码改动**，讨论确认后再动手。
> 数据来源分三类：**【实测】**= 直接读源码/看渲染得到；**【业界】**= 公开资料；**【判断】**= 我的推断，需你确认。

---

## 一、先看清楚这个太阳

### 1.1 素材源码【实测】

`src/assets/meteocons/clear-day.svg`（2283 字节，结构已完整读出）：

```svg
<circle id="Core" cx="64" cy="64" r="19.5"
        fill="渐变(#FBBF24 → #F8AF18)" stroke="#F8AF18"/>
<g id="Rays">   ← 8 条纯色硬边圆角条，全部 fill="#F8AF18"
  <animateTransform type="rotate"
    values="0 64 64; 360 64 64" dur="6s" repeatCount="indefinite"/>
</g>
```

三个关键事实：
1. 核心是半径 19.5/128 的渐变圆盘，主色 `#F8AF18`（**饱和度 94%、亮度 53% 的橙黄**）
2. **8 条等宽硬边射线**，纯色无渐变、无柔化、无长短变化
3. **整组射线 6 秒转一圈，匀速、无限循环**

### 1.2 渲染实拍【实测】

`noon-mostly-clear.png`（1280×800，动画中段截图）显示：
- 左上角一个高饱和橙黄圆盘，外圈 8 根橙黄矩形呈放射状
- 圆盘外侧另有一圈**更亮的斜条纹**（那是 `.boot-halo` 的 `repeating-conic-gradient`，12° 间隔、26 秒转一圈）
- 天空是柔和的多色标渐变，远山带大气透视，整体已偏"氛围场景"

### 1.3 扎眼的五个成因【实测 + 判断】

| # | 成因 | 性质 | 说明 |
|---|---|---|---|
| 1 | **6s 匀速自转的射线轮** | 【实测】 | 直径 300px 的 8 根橙黄硬边条不停打转，视觉侵略性极强，观感接近 loading spinner / 儿童插画。**这是"扎眼"的第一来源** |
| 2 | **两个旋转打架** | 【实测】 | 太阳射线 6s/圈 + `.boot-halo` 的 conic 条纹 26s/圈，同一区域两个不同速率的旋转 → 视觉噪音 |
| 3 | **高饱和纯色冲突** | 【实测】 | `#F8AF18` 在 dusk（紫橙渐变）/ night（冷蓝渐变）的天空上正面撞色——同色系但更饱和，显脏也显跳 |
| 4 | **放得过大** | 【实测】 | `.boot-big-sun` 是 `min(300px, 46vmin)`，把 128px 的图标放大约 2.3 倍，硬边被同步放大 |
| 5 | **风格没跟上** | 【判断】 | v1.22 之后场景已走向"半写实氛围"（Canvas 粒子景深、山体大气透视、多色标天空渐变），**唯独太阳还是"图标语言"**（手绘卡通 + 射线轮）——它是最后一块没跟上的拼图 |

## 二、方案调研：Meteocons 全线排查

### 2.1 换风格 / 换图标都绕不开射线轮【实测】

全库共 **1903 个文件**（475 图标 × 4 风格）。与太阳相关的独立图标只有三种：
`sun-hot` / `sunrise` / `sunset`（各 4 风格）。**没有"无射线的裸太阳"**。

逐一拉取源码对比过三个代表：

| 文件 | 核心 | 射线 | 旋转 |
|---|---|---|---|
| `fill/clear-day.svg`（现用） | r=19.5 渐变实心 | 8 条 `#F8AF18` | 6s rotate |
| `line/clear-day.svg` | r=18 描边圆环 | **8 条，照旧** | **6s rotate，照旧** |
| `fill/sunset.svg` | r=19.5 + 地平线遮罩 | **8 条，照旧** | **6s rotate，照旧** |

**结论：射线轮 + 6s 自转是 Meteocons 的设计签名，不是某个风格的偶发问题。换风格、换 sunset 都治不了。**

### 2.2 一个现成的低成本抓手：官方静态版【实测】

Meteocons 提供 `@meteocons/svg-static` 包，README 明确写 "Static SVG icons (**no SMIL animations**)"。

→ **换成静态版 = 停掉 6s 自转**，射线还在但不再转，侵略性大幅下降。
→ 成本极低：换包重新提取 1 个文件 + 同步 `NOTICE.md`。

### 2.3 业界怎么处理"氛围场景里的太阳"【业界】

- **Apple**：严格区分两种语境——**图标场景**用 SF Symbols（细线射线、静态、小尺寸求辨识度）；**全屏天气背景**里只有光晕，不画具象太阳。
- **SPECTRA**（App Store 天气应用）：主打"将实时天气渲染为**全屏的生成式视觉——没有图标，没有图表，没有杂乱**"。
- 共同点：**氛围场景用"光"，不用"图标"。**

这条对本项目尤其对路——我们的启动动画是 3 秒的全屏氛围，不是 24px 的状态图标，本来就不需要"射线"这种为小尺寸辨识度服务的设计元素。

## 三、候选方案

| 方案 | 做法 | 效果预期 | 成本 | 风险 |
|---|---|---|---|---|
| **A 程序化光源** | 删掉图标，用多层 `radial-gradient` 画"光源"：亮核 + 内辉 + 大气散射，颜色由时段调色板派生 | **最高**：与天空/粒子同源，彻底消除拼贴感 | 中（约半天） | 低 |
| **B 官方静态版** | 换 `@meteocons/svg-static`，停掉 6s 自转 | 中：射线还在但不动了 | 极低（约 1 小时） | 极低 |
| **C 弱化现状** | 缩到 ~32vmin + `saturate(0.75)` + 删掉 halo 的 conic 条纹 | 中低：治标 | 极低（约 0.5 小时） | 极低 |
| **D 只留光晕** | 删掉太阳图标，仅保留柔光层（Apple/SPECTRA 路线） | 高，但"晴天"的具象辨识度会下降 | 低（1–2 小时） | 中（辨识度） |
| E 换 flat/monochrome | 换 Meteocons 风格 | **低**：射线轮照旧 | 低 | 低（效果有限） |

### 推荐：A（程序化光源），并把 D 的柔光层吸收进来

理由：
1. **与 v1.22 已建立的方向一致**——`boot-atmosphere.ts` 已有 `LIGHT_BY_SEGMENT` 光源表，太阳本该是这张表的可视化，而不是一个外来的卡通图标
2. **零素材依赖、零体积增加**（纯 CSS 渐变，几行代码）
3. **四时段自动适配**：正午白金色、黄昏橙红、夜晚冷蓝月华，颜色由调色板派生而非写死 `#F8AF18`
4. 彻底解决"两个旋转打架"和"高饱和撞色"

### 方案 A 的技术要点

1. **三层 `radial-gradient` 叠加**（替代单一圆盘）：
   - 亮核：`rgba(255,250,225,1) → rgba(255,236,180,0.9) 28% → transparent 62%`，直径约 **12vmin**（比现在的 46vmin 小得多）
   - 内辉：`rgba(255,225,170,0.55) → transparent 55%`，直径约 26vmin
   - 大气散射：`rgba(255,200,140,0.22) → transparent 70%`，直径约 48vmin
   - **视觉重量靠辉光撑，不靠大圆盘**——这是消除扎眼感的关键
2. **删掉 `.boot-halo` 的 `repeating-conic-gradient` 条纹**（与太阳旋转打架的元凶），改成同心圆渐变；26s 慢转可保留但不再有硬边条纹
3. **新增 `SUN_BY_SEGMENT` 配置表**（与 `LIGHT_BY_SEGMENT` 并列），四时段各一套色；夜晚换成冷月华色
4. **用极缓的"呼吸"替代机械旋转**：4–6s 一次 `opacity 0.92→1` + `scale 1→1.02`，有生命感但不抢戏

## 四、需要你拍板

1. **要不要保留可辨识的太阳圆盘？** —— A（有小亮核）还是 D（纯光晕，完全不画太阳）？
2. **月亮要不要一起改？** —— 夜晚的 `.boot-big-moon` 同是 Meteocons 卡通月牙，但观感柔和、没那么扎眼，优先级次；是否一并程序化？
3. **晴天的"辨识度"重要吗？** —— 去掉具象太阳后，晴天靠"天空亮度 + 辉光"表达是否够？【判断】我认为够，但这是产品判断
4. **接受自绘吗？** —— 不再使用现成素材，改为代码绘制（本项目已有 Canvas 氛围层的先例，方向一致）
5. 若想先低成本试水，是否接受**先做 B（换静态版停旋转）**看效果，再决定是否上 A？
