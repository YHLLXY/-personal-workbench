# 调研：通知推送的「不挂后台」方案（2026-11-17）

> 触发：用户看到设置页 Web Push 显示「已开启」但收不到通知，问「能不能自己推送？不想一直挂后台」。
> 环境：Android 手机、中国大陆网络、PWA 已安装、已有 Vercel 后端 + 自有域名。

## 1. 现状与根因

| 通道 | 代码位置 | 现状 |
|---|---|---|
| Web Push（VAPID） | `src/sw.ts` push 事件 + `api/reminders.ts` `sendDue` | 订阅成功、服务端返回成功，**但安卓 Chrome 的 Web Push 必须经 FCM**，FCM 在大陆不可用 → 收不到 |
| Server酱（Turbo / SCT） | `sctapi.ftqq.com/<key>.send` | 微信侧可用；依赖方糖服务 |
| Telegram Bot | `api.telegram.org`（服务端出网） | 服务端能发；手机侧大陆需代理 |
| 前台横幅 | `reminder-banner.tsx` | 只在应用打开时有效 |

**关键事实**：安卓上「不挂后台还能收」只有两条路——
1. **厂商推送通道**（小米/华为/OPPO/vivo/荣耀等，App 被杀也能收到）；
2. **App 自建长连接**（ntfy/Gotify，需要前台服务 + 电池不优化，属于「挂一个后台」）。
FCM 属于第 1 类的国际版，在大陆不可用；这也是国产 App 都接第三方推送 SDK 的原因。

## 2. 候选方案对比

| 方案 | 需要常驻 App | 大陆可达 | 自主可控 | 维护状态（2026-11 实测） |
|---|---|---|---|---|
| **Server酱³（SC3）** | 否（走厂商通道） | 是 | 否（第三方，但只在发送时经过） | 活跃，官方推荐接替 Turbo |
| Server酱 Turbo（SCT） | 否（微信服务号） | 是 | 否 | 可用，官方已引导迁移到 SC3 |
| Telegram Bot | 否（Telegram 客户端） | 手机侧需代理 | 中（Bot 归自己，但走 TG） | 活跃，本项目已接 |
| Web Push（VAPID） | 否 | **否**（FCM 被墙） | 是 | 浏览器标准；iOS 16.4+ 走 APNs 可用 |
| **ntfy 自建** | 是（App 前台服务/SSE） | 是（自己的服务器） | **是** | 35.6k star，Apache-2.0，Go，2026-11-16 仍在提交 |
| Gotify 自建 | 是（WebSocket） | 是 | 是 | 16.2k star，Go，活跃 |
| Bark | — | — | — | 9.6k star，**仅 iOS**（Swift） |
| PushDeer | — | — | — | ⚠️ **官方已声明停止维护**（README 顶部警告，Android 版接口权限已停） |

## 3. Server酱³ 的关键事实（这次调研最有用的发现）

- 官方文档：`https://<uid>.push.ft07.com/send/<sendkey>.send`，POST/GET 均可，参数 `title`/`desp`/`tags`/`short`。
- `uid` 可从 SendKey 里提取：正则 `/^sctp(\d+)t/`；SendKey 页面直接给完整 API URL。
- SC3 与 SCT 是**两套用户体系**，SendKey 不通用。官方架了一个 **临时转发**（SCT 入口识别到 SC3 的 key 自动转发），但
  **转发内容会加广告、且声明最多三年**——所以正道是直接调 SC3 的 API，不要依赖转发。
- 官方定位：SC3 专注 App 推送，**大部分手机无需驻留后台**（厂商通道）。免费额度 200 条/天（第三方博客口径，未在官方文档核实）。
- 对我们的影响：`wb_channel_configs.serverchan_key` **不需要改表结构**——key 的形态（`sctp…` vs `SCT…`）就能决定打哪个域名。

## 4. 自建路线（如果以后要「完全自主」）

- **ntfy**：单二进制（Go），Docker 一条命令；PWA 端 `fetch('https://<自己的域名>/<topic>', {method:'POST', body})` 即可发送；
  手机装 ntfy App 订阅私有 topic。**自建场景下不要把 topic 设成公开可猜的名字**。
  注意：不走 FCM 时 App 用前台服务/SSE 维持连接，需把电池策略设为「不限制」，否则会被系统杀掉——**这仍然是「挂后台」，只是挂的是 ntfy 不是工作台**。
- **Gotify**：类似，WebSocket + REST，客户端只有 Android。
- 共同代价：需要一台 7×24 常开的机器（VPS 或家里设备 + 隧道），以及 TLS/备份/升级的运维。

## 5. 结论与建议

1. **近期（零基础设施）**：把「Server酱」通道升级为 **SC3 API**（按 key 前缀自动选端点），得到「不挂后台、走厂商通道、手机装个 App 登录一次」的推送。
   Telegram 保留为备用；Web Push 保留但对安卓大陆用户**明确标注不可用**，不再给出误导性的「已开启」。
2. **中期（可选自建）**：一台常开机器上跑 ntfy，PWA 直接 POST 到自己的域名。这是唯一「完全自主 + 不依赖任何第三方」的路径，但手机侧仍有一个常驻 App。
3. **不采用**：PushDeer（已停维护）、Bark（仅 iOS）。

## 6. 未核实 / 风险

- SC3 免费额度与厂商通道在具体机型上的到达率：需真机实测（用户手机是安卓，正好可验证）。
- SC3 的 key 泄漏即等于推送权限泄漏；设置页已有「掩码显示 + 保存后不可回显」的处理，继续保持。
- 若用户换 iPhone：iOS 16.4+ 的 PWA 装到主屏后可用标准 Web Push（走 APNs，大陆可达），届时可去掉「安卓不可用」的判断。
