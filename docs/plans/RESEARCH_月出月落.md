# 调研：天气详情的「月出月落 + 月相」数据从哪来

> 日期：2026-10-16 · 触发：用户「你既然把太阳的起落线做好了，为什么月亮的不做呢？这样做了的话会更加完整吧」
> 配套计划：`PLAN_V131_月亮_提醒_任务.md`

## 1. 太阳线的现状（要对称复制的东西）

| 环节 | 现状 |
|---|---|
| 数据 | `api/weather.ts` 转发 Open-Meteo `daily=sunrise,sunset`（重庆 29.563N / 106.5516E，`timezone=Asia/Shanghai`） |
| 解析 | `src/lib/weather.ts` 的 `parseWeather` → `DailyForecast.sunrise/sunset`（本地 ISO 字符串） |
| 位置计算 | `sunProgress()` 纯函数（v1.26 从组件里抽出来，可单测） |
| UI | `weather-dialog.tsx` 的 `SunArc`：上排图标+标签 / 中排双色轨道 / 下排大号时间 |

**月亮要「更完整」，就得补齐同样的四层——而第一层是空的。**

## 2. 数据源盘点：没有可用的公共接口

| 源 | 月出/月落 | 月相 | 结论 |
|---|---|---|---|
| Open-Meteo（现用） | ✗ | ✗ | `daily` 只有 sunrise / sunset / sunshine_duration / daylight_duration，没有任何月亮字段 |
| 国内天气源（中国天气网 / 和风） | ✗ | 部分 | 生活指数不含天文；月相字段非标配 |
| ipgeolocation / astronomyapi 一类 | ✓ | ✓ | 需要 key + 免费额度，个人项目多一个外部依赖与配额风险 |
| 自己算 | ✓ | ✓ | 月相与月出月落都是**确定性天文计算**，不需要任何外部服务 |

太阳之所以能走接口，是 Open-Meteo 顺手给了；月亮没有这条捷径，**只能自己算**。

## 3. 自己算 vs 引入 suncalc

月相与月出月落是 Meeus《Astronomical Algorithms》里的标准内容。截断版（ELP-2000/82 取少量项）足以支撑「显示到今天几点几分」的精度。

| 方案 | 体积代价 | 风险 | 判断 |
|---|---|---|---|
| A 手写零依赖（约 120 行） | 0 | 转录错误（符号 / 时角 / 极值插值） | ✅ 采用，风险用测试兜 |
| B `suncalc` 作为运行时依赖 | 11 KB min（约 4.7 KB gzip） | 极低（成熟库） | ✗ 否决 |

**否决 B 的依据不是「我喜欢手写」，是项目门禁自己的文案**：`scripts/check-bundle.mjs` 失败时打印「请优先懒加载 / 换更小的实现（**零依赖优先**）」，而动手前的实测余量只剩（2026-10-16 基线，见 `docs/lessons-learned.md`）：

```
首屏 724 / 790 KB      总量 1129 / 1150 KB      最大 chunk 304 / 340 KB
```

11 KB 会吃掉「JS 总量」剩余余量（21 KB）的 **一半**，换来的是弹窗里的一小节（本轮做完实测 1141/1150，只剩 9 KB）。
（`scripts/check-bundle.mjs` 注释里那行 1103 KB 是 2026-10-15 定基时的旧数——
**门禁注释里的基线数字会过期**，引用前要先实测。）

## 4. 精度与验证策略（这是敢手写的唯一理由）

**不靠自信，靠裁判。**

1. **oracle 差分测试**：`suncalc` 装成 **devDependency**（不进产物），在测试里对随机日期 × 若干纬度逐点比对：月相照度误差 < 0.01、相位误差 < 0.005、月出/月落误差 < 3 分钟。转录层面的符号错、时角错、插值错都会在这里现形。
2. **独立锚点**：日食/月食**按定义**就是新月/满月，与任何实现无关，用作第三方真值。
3. **性质测试**：相位以 29.53 天为周期且连续；同一天月出/月落至多各一次；「整日不落 / 整日不升」被识别，而不是返回一个垃圾时间。

**运行时零依赖、测试时双实现互证**——本项目第一次用这个模式。

## 5. 结论

- 新增 `src/lib/moon.ts`：`moonIllumination(date)` + `moonTimes(date, lat, lon)` + `moonPhaseName(phase)`
- 坐标常量与 `api/weather.ts` 的 UPSTREAM、`vite.config.ts` 的 dev 代理保持一致（沿用「改坐标三处同步」的既有避坑条目）
- UI 与 `SunArc` 对称，紧随其下；月亮用**真实月相**绘制（按照亮比例分盈亏），而不是一个固定圆盘
