## 2026-10-16 · AI 日报上线七个缺陷（v1.28.4 → v1.30.3）

**背景**：AI 日报代码写完、601 个用例全绿、构建与体积门禁通过、迁移也执行了，
**但线上第一次运行就 500，一次都没成功过**。一天内连挖七个缺陷。

### 项目相关的具体根因

| # | 症状 | 根因 | 修法 |
|---|---|---|---|
| 1 | enrich 稳定 500 | 迁移 015 的 CHECK 漏了 `processing`，而 `wb_claim_items()` 正是写这个值 | 迁移 016 重建约束 |
| 2 | 错误只有 `internal error` | PostgREST 报错是普通对象，被 `instanceof Error` 吞掉 | `errText()` 摊平 + `stage` 标签 |
| 3 | build 报「无法解析」 | `deepseek-flash` 思考 token 计入 `max_tokens`，2000 里吃掉 1925 | 默认发 `thinking: disabled`；截断当场抛错 |
| 4 | 「立即生成」报 22P02 | `persistSession:false` 的客户端 `getUser()` 返回 null，`?? ''` 把空串当 uuid | `authUser` 连 `userId` 一起返回 |
| 5 | 生成了但 App 看不到 | 服务端按「库里第一个用户」写日报，**库里有 2 个用户** | 配 `DIGEST_USER_ID`；自检报出用户总数 |
| 6 | 日报「信息太少」 | 编排发给模型的只有 `{eventId,title,category}`，**已生成的摘要一个字没传** | payload 带上 summary；科技配额 4→12 |
| 7 | 处理不完就顺延 | 时间预算按**总量**切，抓取的 11 秒吃掉了摘要的份额 | 改按**剩余**时间 60/40 拆 |

### 项目专属的工程约定（后续迭代遵守）

- **`api/*.ts` 单文件约束**：`telegramGetMe` 这类小工具宁可复制一份，也不能跨文件 import。
- **迁移必须由用户在场执行**，agent 只写文件。写迁移时**建表语句与同一个文件里的函数要对得上**
  （缺陷 1 就是这么来的）。
- **时间预算要区分「固定开销」与「可变开销」**：`/api/hot` 抓 25 个源实测约 11 秒，
  是固定开销，不该从模型份额里扣。
- **服务端替用户猜身份的地方（目前只有 `resolveUserId`）必须让猜测可见**：
  自检报总数与来源，接口响应带 `user` 前 8 位。
- **专属环境变量速查**：`DIGEST_USER_ID`（归属账号，**多用户时必须配**）、`DIGEST_BUDGET_MS`（50000）、
  `DIGEST_FOCUS_CATEGORY`（科技）/`DIGEST_FOCUS_PER_CATEGORY`（12）、`DIGEST_PER_CATEGORY`（4）、
  `LLM_THINKING`（默认关思考）。

## 2026-10-16 · 月亮数据线 + 提醒派生重构 + 任务状态语义（v1.31.0）

**一句话**：三件事撞在同一个母题上——**把「派生数据」当成「独立实体」来维护**。

### 做了什么

| 需求 | 判断 | 改动 |
|---|---|---|
| 「太阳的起落线做好了，为什么月亮的不做」 | Open-Meteo 没有任何月亮字段，免费月亮接口都要 key + 配额 | 新增零依赖 `src/lib/moon.ts`（Meeus 截断级数）+ 天气弹窗「月出月落」一节 |
| 「提醒里为什么还有留存？还可以恢复？是不是设计缺陷」 | 是。提醒是任务/考试/目标的**派生视图**，却被做成了带独立生命周期的实体 | 删掉 `dismissedAt` 与整套「忽略 / 恢复 / 全部忽略 / 已忽略筛选」；服务端改增改删三向对齐 |
| 「紧急程度变底色、焦点加金星金边、进行中与将来到底是什么逻辑」 | `doing` 不影响任何过滤（日期不是今天就在今日页看不见）；`someday` 与日期、重复规则互相打架 | 三态语义补完 + 卡片配色 + 焦点金框 + `focusDate` 复活修复 |

### 关键决策与理由

1. **月亮自己算，但不由自己说了算**：否决 `suncalc` 运行时依赖（11 KB 吃掉 JS 总量余量的**一半**），改手写；
   同时把它装成 **devDependency 只做测试裁判**——365 天 × 中低纬 3 站逐点比对（重庆全年最大偏差 **0.73 分钟**），
   外加日食/月食这类**与任何实现无关**的真值锚。**运行时零依赖、测试时双实现互证**，本项目第一次用这个模式。
2. **逾期口径必须全站唯一**：提醒红底若按「时刻」判，同一个任务会在「今日待办」不红、「提醒中心」红。
   统一按**日期级**（`dueDate < today`），与既有 `overdueTasks` 同尺，理由写死在纯函数注释里。
3. **新建已过期的节点不补发**：否则首次接云端、撤销完成、从「将来」转回来，都会把几十条历史提醒一次性炸出来。
   规则：`scheduled_at <= now` 的新行直接写 `sent_at = now`。**「改期到未来」才重置投递**，改期到过去保留投递记录。
4. **`doing` 纳入今日区**，而不是删掉这个状态：它现在有唯一且可解释的含义（正在推进、要天天看到），
   并且**有出口**（卡片胶囊点一下回普通待办）——旧版只能在编辑弹窗里改，等于没有出口。
5. **删 `dismissed_at` 列必须用户在场**：迁移 `017` 只做 `drop column if exists`，代码不依赖它，
   **先部署再执行**，回滚 SQL 写在文件头。

### 验证

- `npm test` **653 passed / 70 files**（新增 `tests/moon.test.ts` 10 例；reminders 四件套 + 仓储三件套全部改写）
- `npm run build` 通过；`check:bundle` **首屏 724/790 · 总量 1141/1150（本轮 +12 KB）· 最大 chunk 304/340**
- `npm run lint` **11 警告 ≤ 基线 12**（中途出现过 13：新测试里的 `mock.lastCall?.[0]` 触发
  `no-unsafe-optional-chaining`，改成显式取值函数后回落）
- E2E 冒烟 + 真机截图：见文末交付记录

### 反向教训（这一轮最容易再犯的）

- **门禁文件注释里的基线数字会过期**：`check-bundle.mjs` 注释写着 1103 KB（2026-10-15 定基时的数），
  动手前实测已是 **1129 KB**（上一轮日报工作涨的）。**引用前先实测，别把注释当事实。**
- **删一个状态之前，先问「它的出口是什么」**：提醒的「忽略」不是功能，是**没有出口的补丁**；
  真正该给用户的是「处理掉这件事」。
- **别在测试里用 `?.` 取 mock 调用**：`oxlint` 的 `no-unsafe-optional-chaining` 会算进警告基线。
- **行尾符不统一会让脚本改动翻车**：同一仓库里既有 LF 也有 CRLF 文件，多行锚点替换必须先归一化行尾
  （本次在 `task-dialog.tsx` 上因此写坏过一段 JSX，靠 `tsc` 才抓到）。

### 遗留 / 用户侧

- ⚠️ **体积余量只剩 9 KB**（1141/1150）——**这是当前最紧的一条红线**。真到顶了应把 changelog（34 KB chunk）
  改成按需 fetch 的 JSON，**不要删历史条目**。
- 迁移 `017_drop_reminder_dismissed.sql` **待你在 Supabase 执行**（顺序：先部署新版本，再执行）。
- 月亮模块在 |纬度| ≥ 60° 的「擦边日」会与 oracle 差到小时级（那里月亮可能连续 23 小时不落，高度曲线近乎相切，
  两种扫描法对「哪一次算月出」本就没有共识）。本应用只渲染重庆，精度已按纬度分档写进 `tests/moon.test.ts` 顶部。
